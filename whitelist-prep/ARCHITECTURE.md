# Архитектура: сценарий A (БС на last-mile)

## Что именно готовимся

Расширение текущей мобильной модели на домашний интернет **без** закрытия egress из дата-центров.

```
                    СЦЕНАРИЙ A                          СЦЕНАРИЙ B (крайний)
                    ──────────                          ────────────────────
Абонент Wi-Fi  →  [ТСПУ drop-all]  →  ✗ google.com     Абонент + ДЦ  →  [egress ТСПУ]  →  ✗ всё
                  ✓ yandex CDN IP                        ✓ только whitelist в обе стороны
ДЦ (YC VM)     →  провайдер ДЦ     →  ✓ exit за рубежом  ДЦ           →  [egress ТСПУ]  →  ✗ exit
```

Мы готовимся к **сценарию A**, но закладываем задел на раннее обнаружение перехода к B.

## Диверсификация провайдеров

Не держать всё в одном облаке. Минимальный набор:

| Роль | Основной | Резерв |
|------|----------|--------|
| CDN + Origin (контур 1) | Yandex Cloud | — (CDN привязан к YC) |
| Fast VM (контур 2) | Yandex Cloud | VK Cloud / Selectel |
| Exit | 1 страна (EU) | 2-я страна (разный хостер) |
| Домен CDN | example.com | — |
| Домен VM | vm.example.com | vm2.example.com |

## Требования к Fast VM (контур 2)

- **ОС**: Ubuntu 22.04
- **Ресурсы**: 2 vCPU, 2 GB RAM (минимум; для 100+ Мбит/с — 4 vCPU)
- **Сеть**: публичный IP в Yandex Cloud (попадает в whitelist)
- **Порты**: 443 (Reality), 80 (decoy + certbot)
- **Протокол**: VLESS + XTLS-Vision + Reality (TCP/443)
- **Маскировка**: под легитимный сайт (nginx decoy на 80/443 fallback)

## Почему Reality, а не XHTTP на Wi-Fi

| | XHTTP+CDN (контур 1) | VLESS+Reality (контур 2) |
|--|---------------------|--------------------------|
| Throughput | 5–30 Мбит/с | 50–200+ Мбит/с |
| Латентность | +50–150 ms | +10–30 ms |
| Хопы | 3 (CDN→Origin→Exit) | 2 (VM→Exit) |
| Маскировка | CDN SNI | Reality → yandex.ru |
| Зависимость от CDN | Да | Нет |
| Подходит для БС на LTE | **Да** | Да, но избыточен |
| Подходит для Wi-Fi | Работает, но медленно | **Да** |

## Мониторинг перехода A → B

Ключевой индикатор: **исходящий из VM/Origin к exit перестаёт проходить**.

```bash
# На origin/fast-vm — запускать каждые 5 мин
nc -zw3 EXIT_IP 10443 && echo "egress OK" || echo "egress DEAD → сценарий B?"
```

Если egress мёртв, но клиент всё ещё достучался до whitelisted IP — это переход к сценарию B.
В этом случае единственный путь — exit внутри whitelisted-контура (практически нереалистично) или физический канал.

## Порядок деградации (что отвалится первым)

1. CDN OPTIONS начнут throttle'иться (нагрузка растёт)
2. Padding-эвристики на DPI (контур 1)
3. БС на Wi-Fi в крупных городах (Москва, СПб)
4. БС на Wi-Fi в регионах
5. Ужесточение: проверка SNI поверх IP-whitelist
6. Egress-фильтрация из ДЦ (переход к B)

Готовимся к пунктам 1–4. Пункты 5–6 — в RUNBOOK.md.
