# Подготовка к белым спискам: сценарий A (last-mile)

## Целевой сценарий

**Наиболее вероятная эволюция** — не полная изоляция на границе (сценарий B), а расширение текущей модели с мобильного на домашний Wi‑Fi:

| Параметр | Значение |
|----------|----------|
| Где фильтрация | На последней миле (абонент → провайдер → ТСПУ) |
| Что блокируется | Исходящий трафик **пользователя** кроме whitelist |
| Домашний Wi‑Fi | Попадает под БС (через провайдера) |
| Исходящий из ДЦ | **Пока открыт** — origin может ходить на exit за рубежом |
| UDP / QUIC | Заблокирован в режиме БС |
| Разрешённый транспорт | TCP 80, 443, 22 |
| Whitelisted IP | ~0,14% адресного пространства РФ; Yandex Cloud ≈ 20% |

## Двухконтурная архитектура

```
┌─────────────────────────────────────────────────────────────────┐
│ КОНТУР 1: МОБИЛЬНЫЙ (уже работает)                              │
│ Клиент → Yandex CDN (XHTTP+padding) → Origin → Exit → Интернет  │
│ Медленно, максимальная маскировка                               │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ КОНТУР 2: WI-FI / СТАЦИОНАРНЫЙ (готовим сейчас)                │
│ Клиент → YC VM (VLESS+Reality, whitelisted IP) → Exit → Интернет│
│ Быстро, один хоп, без CDN-овер헤да                              │
└─────────────────────────────────────────────────────────────────┘
```

## Структура каталога

```
whitelist-prep/

├── CHECKLIST.md           ← чеклист готовности
├── configs/

│   └── nginx-decoy.conf   ← маскировочный сайт на VM

```

## Быстрый старт

1. Поднять VM в Yandex Cloud (Ubuntu 22.04, публичный IP).
2. Применить `configs/yc-vm-xray.json` + `configs/nginx-decoy.conf`.
3. Обновить exit-сервер по `configs/exit-xray-update.json`.
4. Импортировать оба профиля из `client-profiles/`.
5. Запустить `scripts/health-check.sh` — все проверки должны быть зелёными.
6. Пройти `CHECKLIST.md`.

## Принципы подготовки

1. **Два контура, один exit** — exit-сервер общий, меняются только входные точки.
2. **Диверсификация** — не только Yandex: держать запасной VM в VK Cloud / Selectel.
3. **Мониторинг раньше блокировки** — `probe-whitelist.sh` запускать по cron.
4. **Origin→Exit живёт дольше клиента** — в сценарии A этот хоп критичен; мониторить отдельно.
5. **Не оптимизировать один контур** — готовить оба; на Wi‑Fi скорость, на LTE — CDN.
