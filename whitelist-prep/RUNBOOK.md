# Runbook: эскалация и реагирование

## Уровни угрозы

| Уровень | Симптом | Действие |
|---------|---------|----------|
| 🟢 0 — Норма | google.com доступен, контуры работают | Мониторинг по cron |
| 🟡 1 — БС на LTE | google.com ✗, yandex.ru ✓, CDN/VM ✓ | Переключить мобильный на mobile-cdn |
| 🟠 2 — БС на Wi-Fi | То же на домашнем интернете | Переключить на wifi-fast |
| 🔴 3 — Egress мёртв | VM/Origin не достучаться до exit | **Сценарий B** — см. ниже |
| ⚫ 4 — Полный blackout | Ничего не работает | Физический канал / спутник |

---

## 🟡 Уровень 1: БС активирован на мобильном

**Детект:** `probe-whitelist.sh` → `whitelist_active` на LTE.

**Действия:**
1. Убедиться, что mobile-cdn профиль подключён.
2. `health-check.sh` — CDN OPTIONS должен быть ✓.
3. Если CDN ✗ → переключить на wifi-fast (VM тоже в whitelist).
4. Мониторить: не throttle'ит ли CDN OPTIONS.

**Не паниковать** — это ожидаемое поведение, контуры для этого и готовились.

---

## 🟠 Уровень 2: БС на домашнем Wi-Fi

**Детект:** `probe-whitelist.sh` → `whitelist_active` на Wi-Fi (проводной).

**Действия:**
1. Переключить клиент на **wifi-fast** (Reality на VM).
2. Проверить скорость: `benchmark.sh` — ожидание ≥ 50 Мбит/с.
3. Если wifi-fast медленный → проверить egress VM→exit (`nc -zw5 EXIT_IP 10443` с VM).
4. Если wifi-fast ✗ → fallback на mobile-cdn (медленно, но работает).
5. **Запустить setup резервной VM** в VK Cloud / Selectel (если ещё не сделано).

**Параллельно:**
- Убедиться, что Origin→Exit жив (контур 1 зависит от этого).
- Проверить, не начали ли блокировать Reality (DPI).

## 🔴 Уровень 3: Egress из ДЦ заблокирован (сценарий B)

**Детект:** `health-check.sh` → `Egress → exit :10443 ✗`, но VM/CDN IP доступны с клиента.

**Это переход к сценарию B.** Оба контура мертвы, потому что:
```
Клиент → VM ✓ → Exit ✗     (исходящий из РФ заблокирован)
Клиент → CDN ✓ → Origin ✓ → Exit ✗
```

**Действия (по приоритету):**

### 3.1 Проверить: это egress или проблема exit-сервера?
```bash
# С VM в YC:
nc -zv EXIT_IP 10443          # TCP connect
curl -v telnet://EXIT_IP:10443 # verbose

# С машины ЗА рубежом:
nc -zv EXIT_IP 10443          # exit жив?
systemctl status xray          # xray работает?
```

Если exit жив снаружи, но мёртв с VM — это egress-фильтрация (сценарий B).

### 3.2 Варианты при сценарии B

| Вариант | Сложность | Надёжность | Описание |
|---------|-----------|------------|----------|
| Exit внутри whitelisted-контура | Высокая | Низкая | Прокси на сервере в Yandex/VK Cloud, который ходит «вбок» через peering |
| Satellite / radio | Средняя | Средняя | Starlink, Iridium — вне российской сети |
| Cross-border fiber (корпоративный) | Высокая | Высокая | Аренда канала у оператора с лицензией |
| Физический вывоз данных | Низкая | Низкая | Флешки через границу |

### 3.3 Попытка «бокового» egress через peering
Некоторые российские ДЦ имеют прямой peering с зарубежными сетями вне ТСПУ-контроля. Проверить:
```bash
# С VM: traceroute к exit
traceroute -n EXIT_IP
# Если маршрут идёт через IXP (MSK-IX, DATA-IX) — peering может работать
# Если через магистраль Ростелекома/МТС — скорее всего заблокирован
```

### 3.4 Подготовка к сценарию B (делать заранее)
- [ ] Арендовать VPS у хостера с peering через IXP (не российский ДЦ)
- [ ] Настроить reverse-tunnel: exit инициирует соединение К VM (не VM к exit)
- [ ] Reverse tunnel обходит egress-фильтрацию, если входящий в РФ не блокируется

**Reverse tunnel схема:**
```
Exit (за рубежом) ──исходящий──→ VM (YC, whitelisted IP) :443
                                  ↑
Клиент ──→ VM :443 (Reality) ────┘
         (локальный форвардинг)
```

Настройка reverse tunnel (autossh / frp / xray reverse):
```bash
# На exit-сервере (инициатор):
autossh -M 0 -N -R 10444:127.0.0.1:10443 user@VM_IP

# На VM: клиент подключается к localhost:10444 → попадает на exit
```

Это работает, пока **входящие** соединения в РФ не заблокированы (в сценарии B обычно блокируют исходящие, не входящие).

## Регулярное обслуживание

### Еженедельно
- `health-check.sh` — все ✓
- Проверить срок действия сертификатов: `certbot certificates`
- Проверить логи Xray на аномалии: `journalctl -u xray --since '7 days ago' | grep -i error`

### Ежемесячно
- `benchmark.sh` — скорость не деградировала
- Обновить Xray до последней стабильной версии
- Проверить, не изменились ли IP Yandex CDN / YC
- Ротация Reality shortId (опционально)

### При обновлении Xray
```bash
bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install --version НОВАЯ_ВЕРСИЯ
/usr/local/bin/xray run -test -config /usr/local/etc/xray/config.json
systemctl restart xray
```
